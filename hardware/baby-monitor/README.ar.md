# نظام مراقبة بيئة الطفل بالحساسات — نموذج أكاديمي

العربية · [English](README.md) · [Türkçe](README.tr.md)

جمع مشروع المقرر التاريخي على ESP8266 مدخلات DHT11 لحرارة الجو والرطوبة، وMAX30102 للإشارة الضوئية، وHC-SR501 للحركة، وMAX9814 للصوت، مع عرض عبر Serial وArduino IoT Cloud. لم يكن جهازًا طبيًا معتمدًا. تفصل النسخة البرمجية اللاحقة القراءة الحديثة والمفقودة وغير الصالحة والقديمة؛ ولا تتصل بسحابة حية أو تعيد استعمال الاعتمادات القديمة. لا ندعي دقة سريرية أو قياسات طفل قابلة لإعادة الإنتاج.

تضم `assets/` خريطة الإشارات التاريخية D3/D4/D2/D1/A0 وقصاصات من تقرير المقرر. ينقل الرسم المرجعي المشروط DHT11 وحساس الحركة بعيدًا عن أطراف الإقلاع، لكنه لا يفترض وجود منظم جهد أو محول مستويات في وحدة MAX30102 مجهولة الإصدار، ولا أن دخل A0 في لوحة NodeMCU يقبل خرج MAX9814. اقرأ [دليل التوصيل بثلاث لغات](WIRING.md). لا تركّب الجهاز اعتمادًا على صورة Fritzing التاريخية.

اختبار المنطق محليًا: `g++ -std=c++11 -Wall -Wextra -Werror tests/core_tests.cpp -o baby-core-tests` ثم شغّل الناتج. يترجم اختبار التفاعل `tests/firmware_interaction.cpp` بتعريفات محلية مع `-Itests/stubs -Isrc -DMONITOR_LANGUAGE=0` أو 1 أو 2. هذه فحوص اصطناعية وليست تحققًا سريريًا. نجح أيضًا بناء المرشح لهدف NodeMCU/ESP8266 بإصدارات أداة ولوحة ومكتبات محددة، موثقة في [عقد البناء](build-target.json). أصدرت مكتبة MAX3010x الخارجية تحذيرًا بإعادة تعريف `I2C_BUFFER_LENGTH`. لم يُختبر جهاز فعلي أو توصيل أو معايرة أو قياسات سريرية.

[دراسة الموقع](https://yahyaalali.com/content-library/project/baby-monitor/) و[NOTICE](NOTICE) يوضحان النطاق والحقوق. `secrets.example.h` قالب وهمي فقط؛ لا تتضمن الحزمة `thingProperties.h` أو `sketch.json` أو مفاتيح سحابة أو كلمات Wi-Fi أو تاريخ المصدر الخاص. لا تُمنح رخصة إعادة استخدام عامة.
